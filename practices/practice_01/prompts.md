## Master Prompt v1

Соберите здесь контракт второго запуска. Не копируйте все документы целиком — ставьте ссылки на файлы и переносите только необходимый для задачи контекст.

### 1. Цель и роль

- Цель: на основе TRAINING_PR.diff выявить минимальные изменения для стабилизации API `/api/reviews` и подготовить проверяемые артефакты (AS IS/TO BE, тест-план, ADR).
- Роль AI: структурированный ревьюер и помощник валидации требований, предлагающий минимальные изменения без расширения области.

### 2. Входы и источники

- Обязательный вход: practices/practice_01/TRAINING_PR.diff.
- Разрешённые файлы и источники: practices/practice_01/context.md, problem.md, analysis.md.
- Context Pack — факты, правила, примеры и ограничения: см. context.md (точка входа POST /api/reviews; формат входа/выхода; отсутствие валидации и обработчиков; хороший/плохой примеры).

### 3. Задача и артефакты

- Что сделать: провести структурное ревью diff, предложить минимальные изменения (валидация, лимит, обработка ошибок, контракт ответа), обновить таблицы analysis.md, product_management.md, tests_*.
- Что вернуть: список найденных проблем с evidence (ссылка на строки diff), предложения изменений, статусы кодов и проверочные сценарии.

### 4. Формат результата

- Структура ответа: список пунктов Problem → Evidence (файл:строки) → Impact → Change → Test.
- Ограничения объёма: не более 20 пунктов; не повторять одно и то же evidence.

### 5. Полномочия и запреты

- Разрешено: делать выводы только по файлам в practices/practice_01; предлагать минимальные исправления.
- Запрещено: придумывать недоказуемые требования; менять файлы вне папки практики; расширять область (auth, биллинг, i18n).

### 6. Рабочий процесс и остановка

- Шаги: 1) Прочитай diff. 2) Сопоставь с context.md и problem.md. 3) Составь список проблем с evidence. 4) Сформируй минимальные изменения и статусы ответов. 5) Предложи проверки (unit/integration/e2e/load).
- Когда остановиться и запросить человека: если требуется выбрать значение лимита N или коды ошибок вне 400/413/502/503.

### 7. Проверки и evidence

- Как проверять утверждения: каждое утверждение подтверждать ссылкой на файл и строки из TRAINING_PR.diff.
- Какое evidence сохранить: фрагмент строки и номер; для гипотез — явная пометка и запрос подтверждения.

### 8. Definition of Done

- Задача закончена, когда: заполнены context, problem, analysis, product_management, project_management, adr, tests_*; в prompts.md есть P1-01 и P1-02; в предложениях нет недоказуемых требований.

## Сравнение двух запусков

| Проверка | Zero-shot | С master prompt | Вывод команды |
|---|---|---|---|
| Есть ссылка на файл или строку | ✓ | ✓ | С master prompt обязательна ссылка |
| Вывод подтверждён diff или правилом | Частично | ✓ | Требуем evidence |
| Соблюдены границы AI | Нет | ✓ | Нельзя расширять область |
| Есть воспроизводимая проверка | Частично | ✓ | Должен быть сценарий |
