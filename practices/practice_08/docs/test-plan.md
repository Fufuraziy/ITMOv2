# Клиентские тесты: что проверяется

Стек: Vitest 1.6 + jsdom, Testing Library (React 16.3), `@testing-library/user-event` 14. Запуск: `cd app/frontend && npm test`.
Итог последнего прогона: **7 файлов, 78 тестов, все зелёные** ([evidence/frontend-tests.txt](evidence/frontend-tests.txt)).

## Как подменяются ответы сервера

- [`src/test/server.ts`](../app/frontend/src/test/server.ts) подменяет `fetch` (`vi.stubGlobal`) и отвечает в формате Go-бэкенда: `list()` — 200 `{total, suggestions}`, `created()` — 201 заявка без email, `invalid()` — 400 `invalid_suggestion` + `fields`, `duplicate()` — 409, `internal()` — 500, `'network-error'` — `fetch` бросает `TypeError`, `deferred()` — ответ, который тест отпускает сам (так проверяется состояние «ждём сервер»).
- [`src/test/contract.test.ts`](../app/frontend/src/test/contract.test.ts) сверяет эти фабрики с ответами **живого** API, записанными в [`api-samples.json`](../app/frontend/src/test/api-samples.json) (`201`, `200`, `400`, `409`). Если бэкенд поменяет формат, а моки нет, этот тест упадёт.
- Каждый тест считает запросы `POST /suggestions` (`posts(fetchMock)`) и проверяет тело запроса, а не только экран.

## Что предложил AI и что пришлось исправить

Тесты писал Claude Code по сценарию из README практики. Я сверял каждый тест с действием пользователя и прогонял.

1. **Нашли настоящую ошибку.** Тест «фокус возвращается на кнопку» упал: после закрытия диалога фокус уходил на `body`. Radix возвращает фокус только на свой `DialogTrigger`, а ручной `focus()` он перебивал. Исправлено через `onCloseAutoFocus`.
2. **Проверка блокировки была неверной.** Первый вариант проверял `button.disabled`, но кнопки в `<fieldset disabled>` блокируются, а свойство остаётся `false`. Кнопкам поставлен явный `disabled`, у полей тест проверяет `:disabled`.
3. **Тест не находил вкладку.** Он искал вкладку по роли, пока открыт модальный диалог. Radix ставит фону `aria-hidden`, поэтому нужен `hidden: true`. Это ошибка теста, а не кода.
4. **Уведомление находилось дважды.** sonner дублирует текст в aria-live‑регионе, поэтому `findAllByText`.
5. **Не хватало проверки на гонку.** Добавлен тест с двумя `requestSubmit()` в одном тике: без него защита от повторной отправки проверялась только через `disabled` у кнопки.
6. **Моки не сверялись с API.** Добавлен контрактный тест с записанными ответами живого API: без него моки могли бы разойтись с бэкендом.
