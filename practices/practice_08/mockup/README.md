## Основной сценарий

Посетитель не нашёл подходящую подборку и предлагает куратору новую: вкладка «Заявки куратору» → «Предложить подборку» → форма в диалоге → «Отправить заявку» → диалог закрывается, появляется уведомление «Заявка отправлена», заявка первой в списке с пометкой «новая».

## Что предложил AI

По первому запросу v0 за 3 минуты собрал прототип со всеми девятью запрошенными состояниями. Заказанные цвета, шрифт Onest, подписи у всех полей и звёздочки обязательных полей он соблюл сам. Сам добавил счётчик символов «57/500» под комментарием, подсказки под полями («От 3 до 80 символов», «От 300 до 20 000 ₽») и пустое состояние с иконкой.

## Что я изменил после проверки (запрос 2)

Прошёл все 9 состояний на десктопе и на 375 px и нашёл:

1. **Декор не про продукт:** иллюстрация с цветком, стикер и статус «Собрано с заботой», капслок‑надзаголовки, слоган в подвале. В [`docs/design.md`](../app/docs/design.md) проекта капслок‑надзаголовки и украшения, кроме фото товаров, прямо запрещены. Убрано: заголовок слева, кнопка справа, сразу список.
2. **Стрелки «→» в кнопках** (тоже запрещены в design.md) убраны.
3. **«Отправка» выглядела как очищенная форма:** значения были светло‑серыми, как плейсхолдеры. Попросил оставить данные читаемыми и заблокировать «Отмена».
4. **Ошибка и подсказка шли подряд** («Укажите целое число от 300 до 20 000 ₽» + «От 300 до 20 000 ₽»). Теперь подсказка скрывается, пока видна ошибка. Тексты ошибок переписаны так, чтобы было ясно, что исправить. Повод по умолчанию — «без повода».
5. **Alert ошибки сервера стоял над формой, далеко от кнопки.** Перенесён к кнопкам.
6. **Не было связи с поиском.** Добавлен экран «Поиск без результатов» с кнопкой «Предложить такую подборку».
7. **Фокус и выделение новой карточки** заданы явно (3 px, `#2C7A45`).

v0 выполнил всё, кроме показа фокуса в статичном состоянии «Диалог с данными». Фокус виден при реальной навигации с клавиатуры ([v2/11](screens/v2/11-focus.jpg)), и в коде он есть.

## Синхронизация с реализацией (запрос 3)

При сборке интерфейса на настоящем API часть решений изменилась, и макет обновлён под них:

- текст уведомления об успехе называет заявку («"Название" — куратор посмотрит её в ближайшие дни»);
- Alert ошибки отправки: заголовок + текст + маленькая кнопка «Повторить» под ним;
- ошибка загрузки списка — Alert слева, а не карточка по центру;
- поля «Повод» и «Бюджет» стоят в одну строку от 640 px;
- экран поиска показывает настоящие фильтры: чипы‑поводы, бюджеты, сортировку;
- подвал убран.

## Макет ↔ интерфейс

| Элемент макета | Компонент shadcn/ui в коде |
|---|---|
| вкладки‑подчёркивания в шапке | `Tabs` / `TabsList variant="line"` / `TabsTrigger` ([App.tsx](../app/frontend/src/App.tsx)) |
| «Предложить подборку», «Отмена», «Отправить заявку», «Повторить» | `Button` (default / outline, size lg/sm) |
| диалог с формой | `Dialog`, `DialogContent`, `DialogHeader`, `DialogFooter` |
| подписи, подсказки, ошибки полей | `Field`, `FieldLabel`, `FieldDescription`, `FieldError` |
| поля | `Input`, `Textarea`, `NativeSelect` |
| «Отправляем…» | `Spinner` внутри `Button` |
| ошибки загрузки и отправки | `Alert` variant="destructive" |
| карточка заявки, бейджи повода и «новая» | `Card`, `Badge` |
| скелетоны списка | `Skeleton` |
| уведомление «Заявка отправлена» | `Sonner` (`toast.success`) |
| чипы поводов и бюджетов в поиске | `Toggle` |

Скриншоты готового интерфейса на настоящем API лежат в [`../docs/screens/`](../docs/screens/).
