# Исправленные ошибки

| # | Где | Ошибка | Исправление |
|---|---|---|---|
| 1 | `API_KEY` | Секрет `sk-prod-...` захардкожен в коде | Ключ читается из `NOTES_API_KEY`; без него удаление запрещено |
| 2 | `normalize_tags` | Изменяемый аргумент по умолчанию `seen=[]` копил теги между вызовами, и у следующих заметок теги терялись | `seen` создаётся внутри функции как `set()` |
| 3 | `list_notes` | `offset = page * size` при нумерации страниц с 1: первая страница пропускалась | `offset = (page - 1) * size` |
| 4 | `list_notes` | Соединение с БД не закрывалось (утечка) | Все функции работы с БД используют `with closing(...)` |
| 5 | `search_notes` | SQL-инъекция: `q` подставлялся в запрос через f-строку | Параметризованный запрос `LIKE ? ESCAPE '\'`, символы `%` и `_` экранируются |
| 6 | `get_stats` | `ZeroDivisionError` (ответ 500) при пустой таблице | Если заметок нет, среднее равно 0 |
| 7 | `do_POST` | `except Exception` проглатывал любую ошибку и отвечал 200 `{"status": "ok"}` | Входные данные проверяются явно: на ошибку ответ 400 с текстом, на успех 201 |
| 8 | `do_DELETE` | Проверка ключа была инвертирована (`==`): с правильным ключом ответ 403, без ключа удаление проходило | `hmac.compare_digest` и отказ, если ключ не совпал |
| 9 | `do_DELETE` | Ответ 204 отправлялся с телом; удаление несуществующей заметки отвечало 204 | 204 без тела, для несуществующего id ответ 404 |
| 10 | `do_GET` / `do_DELETE` | `int()` от `page`, `size`, `id` без проверки: на мусорный ввод ответ 500 | `parse_positive_int`: ответ 400, `size` не больше 100 |
| 11 | `HOST` | Сервис слушал `0.0.0.0` | По умолчанию `127.0.0.1`, адрес и порт меняются через `NOTES_HOST` / `NOTES_PORT` |

## Запуск после исправлений

```bash
NOTES_API_KEY=<ключ> python app.py
```
