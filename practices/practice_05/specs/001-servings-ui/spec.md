# Feature Specification: Переключатель порций ×1 / ×2 / ×4 (UI)

**Feature Branch**: `practice_05` (отдельная ветка под фичу не создавалась)

**Feature Directory**: `specs/001-servings-ui`

**Created**: 2026-10-21

**Status**: Draft

**Owner**: команда 1 — экраны и поведение страницы. Масштабирование количеств, итогов и ссылок на корзину — команда 2; здесь только то, что UI от неё получает (последний раздел, согласован с `specs/002-servings-logic`).

**Input**: User description: "Переключатель порций ×1/×2/×4 на странице выдачи подборок. Опиши экраны и действия, состояния (загрузка, пусто, ошибка, выбранные порции), что видит пользователь вместо или рядом с кнопкой «В корзину», пока cart_url существует только для ×1. Код не меняй. В конце отдельным разделом «Что мне нужно от логики»: поля, параметры, ошибки."

## Контекст

Сейчас каждая карточка подборки в выдаче показывает фото товаров, название, описание, теги, итог «≈ 1 111 ₽», кнопку «Перенести в корзину ВкусВилла» (открывает vkusvill.ru в новой вкладке) и раскрывающийся состав-«чек»: товар, количество, единица, цена за единицу. Подборка собрана куратором на один набор — это **×1**.

Фича выходит одним релизом с пересборкой каталога: к релизу у каждой подборки есть готовые ссылки на корзину для ×1, ×2 и ×4, и логика отдаёт все три варианта в одном ответе (решения 1A, 5A, 6A). Состояния «ссылки на ×N нет» в выпущенной фиче не бывает.

Термины:

- **Множитель (×N)** — во сколько раз увеличить подборку: ×1 — как собрал куратор, ×2 и ×4 — количества масштабируемых товаров увеличены в 2 и 4 раза. Товары, которые куратор пометил «не масштабируется» (кофе, варенье, специи), остаются как в ×1.
- **Корзина ×N** — ссылка на vkusvill.ru, которая кладёт в корзину подборку сразу с количествами для ×N.

## Clarifications

### Session 2026-10-21

- Q: Переключатель порций свой в каждой карточке или один общий на страницу? → A: Свой в каждой карточке, по умолчанию ×1; общего переключателя в панели фильтров нет.
- Q: Что делать с зелёной кнопкой корзины при ×2/×4 без ссылки? → A: Заменить: зелёная кнопка исчезает, на её месте подсказка и кнопка второго плана «Открыть корзину ×1». *Снято решением 5A/6A арбитража ниже: ссылка ×N есть всегда.*
- Q: Как долго помнить выбранный множитель? → A: До перезагрузки страницы; после перезагрузки и при открытии по ссылке — ×1. В адрес страницы и хранилище браузера множитель не пишется.

### Арбитраж контракта UI ↔ логика, 2026-10-21

Расхождения со `specs/002-servings-logic/spec.md` разобраны, решения принял человек. Номер — пункт таблицы расхождений.

- 1A: в каждой подборке приходит массив всех трёх вариантов; переключение не делает запросов.
- 2B: внутри варианта множитель называется `multiplier`; `servings` — параметр запроса и применённый множитель подборки.
- 3A: у каждого товара есть `base_quantity` — количество для ×1.
- 4A: UI учитывает `scalable`: «было» показывается только у масштабируемых товаров.
- 5A, 6A: состояний «ссылки нет», «собираем корзину», «ошибка сборки» нет; фича выходит вместе с пересборкой каталога.
- 7B: у варианта есть `available` (сейчас всегда `true`); ветка «множитель недоступен» в UI остаётся на будущее.
- 8A: наличие вариантов в ответе — признак, что бэкенд уже с фичей; без них карточка как до фичи.
- 9A: UI не передаёт `servings` в поиск; пометку «больше бюджета» ставит сам.
- 11 (по нумерации человека — 10B): у ошибок есть машинный `code`, UI различает ошибки по нему.
- 12 (по нумерации человека — 11): ошибки сборки ссылки сняты вместе с 5A.
- 13 (по нумерации человека — 12B): откат переключателя при ошибке запроса варианта — не применяется: по 1A отдельного запроса нет (приоритет у решения с меньшим номером).

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Увидеть подборку на ×2 / ×4 (Priority: P1)

Пользователь готовит на компанию. В карточке «Борщ на большую кастрюлю» он нажимает «×2» и сразу видит итог и количества товаров для двух наборов, не уходя со страницы.

**Why this priority**: это основная ценность фичи — понять, сколько купить и сколько это стоит.

**Independent Test**: открыть выдачу, в любой карточке выбрать ×2 и ×4 — итог и состав меняются, остальные карточки, фильтры и адрес страницы не меняются, новых запросов к API нет.

**Acceptance Scenarios**:

1. **Given** выдача загружена и карточка в ×1, **When** пользователь нажимает «×2», **Then** «×2» отмечен выбранным, итог показывает `total_price` варианта ×2 с пометкой множителя («≈ 2 222 ₽ · ×2»), а в составе количества варианта ×2.
2. **Given** карточка в ×2, **When** пользователь нажимает «×1», **Then** итог, состав и кнопка корзины такие же, как до переключения.
3. **Given** в выдаче несколько карточек, **When** в первой выбран ×4, **Then** остальные карточки остаются в ×1.
4. **Given** в карточке выбран ×2, **When** пользователь меняет запрос или фильтр и эта подборка остаётся в выдаче, **Then** в ней по-прежнему выбран ×2.
5. **Given** фокус на переключателе, **When** пользователь меняет выбор с клавиатуры, **Then** выбор меняется, а программа чтения с экрана объявляет «Порции: ×2, выбрано» и новый итог.
6. **Given** в подборке есть товар с `scalable: false` (например, кофе 1 шт), **When** выбран ×4, **Then** у этого товара в составе «1 шт» без пометки «было», а у масштабируемых товаров — количество ×4 и мелко «было» для ×1.

### User Story 2 — Корзина ×N одной кнопкой (Priority: P1)

Пользователь выбрал ×2 и переносит увеличенную подборку в корзину ВкусВилла одной кнопкой, как сейчас ×1.

**Why this priority**: главное обещание сервиса — «одной кнопкой в корзину»; без неё переключатель только показывает цифры.

**Independent Test**: выбрать ×2 в любой карточке — основная кнопка ведёт на `cart_url` варианта ×2; состав корзины совпадает с составом карточки.

**Acceptance Scenarios**:

1. **Given** выбран ×2, **Then** основная кнопка называется «Перенести в корзину ВкусВилла · ×2» и открывает `cart_url` варианта ×2 в новой вкладке.
2. **Given** выбран ×1, **Then** кнопка и ссылка такие же, как до фичи.
3. **Given** пользователь открыл корзину ×2 и вернулся на страницу, **Then** в карточке по-прежнему выбран ×2.

---

### User Story 3 — *Снято* (решения 5A, 6A)

Сценарии «ссылку ×N можно получить только по запросу», «Собираем корзину ×2…», повторное использование полученной ссылки и поздние ответы сборки сняты: ссылки всех вариантов приходят сразу в ответе (1A), сборки по запросу нет (5A).

---

### User Story 4 — Недоступный множитель и выкат (Priority: P3)

Ветка на будущее и на время выката: пользователь понимает, почему множитель неактивен, а на старом бэкенде карточка работает как раньше.

**Why this priority**: сейчас логика всегда отдаёт `available: true` и все три варианта (7B); ветка нужна, чтобы позже не менять UI.

**Independent Test**: на тестовых данных с `available: false` у ×4 и на ответе без вариантов — видны неактивный сегмент с причиной и карточка без переключателя.

**Acceptance Scenarios**:

1. *Снято (5A, 12)*: ошибки сборки корзины нет.
2. **Given** у варианта ×4 `available: false`, **Then** «×4» виден, но неактивен, а `reason` из ответа видна под переключателем при фокусе или наведении и объявляется программой чтения с экрана.
3. **Given** в подборке нет массива вариантов (бэкенд ещё без фичи), **Then** переключателя в карточке нет, карточка выглядит и работает как сейчас.

### Экраны и состояния

#### Где находится переключатель

В каждой карточке, в блоке покупки, перед итогом: подпись «Порции» и три сегмента «×1 ×2 ×4», выбран ровно один, по умолчанию ×1. В общую панель фильтров переключатель не выносится: итог и ссылка у каждой подборки свои. На узком экране (от 360 px) переключатель стоит отдельной строкой над итогом и кнопкой.

#### Состояния страницы

| Состояние | Что видит пользователь | Переключатель |
|---|---|---|
| Первая загрузка выдачи | строка «Ищем подборки…» на месте выдачи | нет (нет карточек) |
| Обновление выдачи после смены запроса или фильтра | прежняя выдача остаётся на месте до прихода новой | работает; выбор по каждой подборке сохраняется |
| Пусто | как сейчас: «Ничего не нашлось…» и «Сбросить поиск» | нет |
| Каталог не отвечает | как сейчас: «Каталог не отвечает. Обновите страницу через минуту.» | нет |

#### Состояния карточки

| Состояние | Переключатель | Итог | Кнопка «В корзину» | Состав |
|---|---|---|---|---|
| ×1 (по умолчанию) | выбран ×1 | ≈ 1 111 ₽ | зелёная «Перенести в корзину ВкусВилла» — как сейчас | количества ×1 |
| ×N | выбран ×N | ≈ 2 222 ₽ · ×2 | зелёная «Перенести в корзину ВкусВилла · ×2», ссылка варианта ×N | количества ×N; у масштабируемых — «было» для ×1 |
| ×N недоступен (на будущее, 7B) | сегмент ×N неактивен, `reason` при фокусе/наведении | без изменений | без изменений | без изменений |
| Вариантов нет (8A) | нет | как сейчас | как сейчас | как сейчас |

#### Итог и бюджет

- Итог для ×N — `total_price` варианта из ответа; страница его не пересчитывает.
- В поисковый запрос UI `servings` не передаёт: фильтр «до 500 / 1 000 / 2 000 ₽» и сортировка по цене работают по итогу ×1 (9A).
- Если выбран бюджет и `total_price` выбранного варианта его превышает, рядом с итогом мелкая пометка «больше бюджета»; сравнение делает UI.

#### Тексты (черновик)

| Где | Текст |
|---|---|
| Подпись группы | Порции |
| Сегменты | ×1, ×2, ×4 |
| Итог ×N | ≈ 2 222 ₽ · ×2 |
| Кнопка ×N | Перенести в корзину ВкусВилла · ×2 |
| Строка состава ×N, масштабируемый товар | 2 шт · было 1 шт |
| Строка состава ×N, немасштабируемый товар | 1 шт |
| Пометка бюджета | больше бюджета |

### Edge Cases

- **Весовые товары**: 0,35 кг × 4 = 1,4 кг — дробь через запятую, без лишних нулей; количество уже округлено логикой.
- **Немасштабируемые товары**: их количество при любом ×N как в ×1, «было» не показывается; поэтому итог ×N может быть заметно меньше «итог ×1 × N».
- **Лимит корзины ВкусВилла** (до 40 на позицию): логика гарантирует его проверкой каталога, все варианты сейчас доступны. Если когда-нибудь придёт `available: false`, сегмент неактивен с причиной (US4.2).
- **Выбранный множитель стал недоступен**: в карточке выбран ×4, а следующий ответ поиска пришёл с ×4 `available: false` — карточка показывает ×1 (отмечен «×1», итог и ссылка ×1); сегмент «×4» неактивен с причиной.
- **Округление итога**: итог ×N может отличаться от «итог ×1 × N» на рубль из-за одного округления суммы — показываем число логики. Пример «≈ 2 222 ₽ · ×2» — см. «Открытые вопросы».
- **Быстрое переключение** ×2 → ×4 → ×1: запросов нет, на экране сразу последний выбор.
- **Подборка ушла из выдачи и вернулась** после смены фильтра: выбор сохраняется до перезагрузки страницы.
- **Перезагрузка или ссылка на выдачу**: все карточки открываются в ×1; множитель в адрес страницы не попадает.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Каждая карточка подборки в выдаче MUST иметь переключатель «Порции» с вариантами ×1, ×2, ×4; выбран ровно один, по умолчанию ×1.
- **FR-002**: Выбор в одной карточке MUST NOT менять другие карточки, фильтры, сортировку и адрес страницы.
- **FR-003**: При выборе ×N итог и количества в составе MUST браться из варианта ×N в уже полученном ответе, без нового запроса; страница сама их не вычисляет.
- **FR-004**: В составе при ×N каждая строка MUST показывать количество варианта ×N; у товаров со `scalable: true` — второстепенно и количество для ×1 (`base_quantity`), у товаров со `scalable: false` — без «было».
- **FR-005**: Основная кнопка корзины при ×N MUST открывать `cart_url` варианта ×N в новой вкладке; её подпись при ×2 и ×4 MUST содержать множитель.
- **FR-006**: *Снято (5A, 6A)* — состояния «ссылки ×N нет» не бывает.
- **FR-007**: *Снято (5A)* — сборки ссылки по запросу нет.
- **FR-008**: *Снято (5A, 12)* — ошибки сборки ссылки нет.
- **FR-009**: Вариант с `available: false` MUST быть виден, но неактивен; `reason` MUST быть доступна при фокусе, наведении и программе чтения с экрана. Сейчас логика всегда отдаёт `available: true` (7B). Если выбранный множитель стал недоступен, карточка MUST показывать ×1.
- **FR-010**: Если в подборке нет массива вариантов, карточка MUST выглядеть и работать как до фичи, без переключателя (признак старого бэкенда при выкате, 8A).
- **FR-011**: Выбор множителя MUST сохраняться для подборки при обновлении выдачи до перезагрузки страницы; после перезагрузки и при открытии по ссылке — ×1. Множитель MUST NOT сохраняться в адресе страницы или хранилище браузера.
- **FR-012**: *Снято (1A)* — переключение не делает запросов, поздних ответов нет.
- **FR-013**: *Снято (1A, 5A)* — ссылки всех вариантов приходят сразу.
- **FR-014**: Переключатель MUST управляться с клавиатуры; группа имеет подпись «Порции», выбранный вариант и новый итог объявляются программой чтения с экрана.
- **FR-015**: При первой загрузке выдачи страница MUST показывать «Ищем подборки…».
- **FR-016**: Если выбран бюджет и `total_price` выбранного варианта его превышает, рядом с итогом MUST быть пометка «больше бюджета»; сравнение делает UI. Фильтр и сортировка по-прежнему работают по итогу ×1.
- **FR-017**: Карточка во всех состояниях MUST читаться на экране шириной 360 px без горизонтальной прокрутки.
- **FR-018**: UI MUST NOT передавать `servings` в `GET /collections` (9A).
- **FR-019**: Ошибка API MUST передаваться в UI со статусом ответа и полем `code`; UI MUST NOT разбирать текст `error` (11/10B). Сейчас все ошибки поиска показывают одно сообщение (раздел «Ошибки»); `code` — точка различения для будущих разных сообщений.

### Key Entities

- **Вариант порций** — один множитель подборки из ответа логики: `multiplier` (1, 2 или 4), `total_price` в рублях, количества товаров по `xml_id`, `cart_url` (есть всегда), `available` и `reason` (только при `available: false`).
- **Выбор пользователя** — какой множитель выбран в какой подборке на открытой странице; живёт до перезагрузки.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: После нажатия ×2 или ×4 итог и состав обновляются без видимой задержки (до 0,2 с), без запросов к API и без перезагрузки выдачи.
- **SC-002**: Ноль ситуаций, где кнопка обещает корзину ×N, а открывает другую, — проверяется для всех подборок каталога и всех трёх множителей.
- **SC-003**: *Снято (5A, 6A)* — коридорный тест сценария «ссылки нет» не нужен.
- **SC-004**: От выбора ×N до открытой вкладки vkusvill.ru — не больше 2 нажатий в любом состоянии, кроме «недоступен».
- **SC-005**: Все действия с переключателем выполнимы только с клавиатуры, программа чтения с экрана озвучивает выбранный множитель и итог.
- **SC-006**: Карточка в любом состоянии помещается в экран шириной 360 px без горизонтальной прокрутки.

## Assumptions

- ×N — количества масштабируемых товаров подборки умножены на N; немасштабируемые не меняются. Сколько человек кормит ×1, неизвестно, поэтому подписи «×1 / ×2 / ×4», а не «на 2 персоны».
- Переключатель свой у каждой карточки, общего на страницу нет (решено в Clarifications): итог и ссылка у подборок разные.
- Множитель не попадает в адрес страницы: ссылкой на выдачу делятся без него.
- Фильтр бюджета и сортировка по цене на странице остаются по итогу ×1: UI не передаёт `servings` в поиск, хотя логика его принимает (9A).
- Ссылки на корзину для всех трёх множителей собираются куратором заранее, вместе с каталогом; фича выходит одним релизом с пересборкой каталога (5A, 6A).
- Бэкенд, `curate.mjs`, MCP `vv-collections` и контракт — вне этой спеки. Внешний вид при реализации делается через skill frontend-design.

## Что мне нужно от логики

Согласовано с командой 2 на арбитраже 2026-10-21; подробности и гарантии — раздел «Что я гарантирую UI» в `specs/002-servings-logic/spec.md`. UI ничего не умножает и не собирает ссылки сам. Изменения контракта (`docs/requirements.md`) согласует человек.

### Поля

Для каждой подборки — и в поиске (R2), и в подборке по id (R4):

| Поле | Зачем UI |
|---|---|
| Массив `variants`, всегда три: ×1, ×2, ×4 | рисовать переключатель без запросов (FR-001, FR-003); нет массива — нет переключателя (FR-010) |
| `variants[].multiplier` — 1, 2 или 4 | какой сегмент |
| `variants[].total_price` — целые рубли | итог в карточке (FR-003), пометка бюджета (FR-016) |
| `variants[].quantities` — `{xml_id: количество}` в единице товара | состав ×N (FR-004) |
| `variants[].cart_url` — всегда строка | кнопка корзины ×N (FR-005) |
| `variants[].available` (сейчас всегда `true`), `reason` при `false` | неактивный сегмент с причиной (FR-009) |
| `products[].base_quantity` | «было» для ×1 (FR-004) |
| `products[].scalable` | показывать ли «было» (FR-004) |

Вариант ×1 совпадает с текущими полями подборки (`total_price`, `cart_url`, `products[].quantity`).

### Параметры

- `servings` в `GET /collections` UI не передаёт (FR-018). Отдельных запросов за вариантами или ссылками нет.

### Ошибки

UI различает ошибки по `code` (FR-019); тело — `{"error": "…", "code": "…"}`, значения `code`: `invalid_query` (400), `collection_not_found` (404), `internal_error` (500) — по `specs/002-servings-logic/contracts/http-api.md`.

| Ситуация | Что покажет UI |

| Поиск не ответил или `500` | как сейчас: «Каталог не отвечает. Обновите страницу через минуту.» |
| `400` на поиске (неверный `max_price`/`sort`) | как сейчас |
