# Feature Specification: Переключатель порций ×1 / ×2 / ×4 (UI)

**Feature Branch**: `practice_05` (отдельная ветка под фичу не создавалась)

**Feature Directory**: `specs/001-servings-ui`

**Created**: 2026-10-21

**Status**: Draft

**Owner**: команда 1 — экраны и поведение страницы. Масштабирование количеств, итогов и ссылок на корзину — команда 2; здесь только то, что UI от неё ждёт (последний раздел).

**Input**: User description: "Переключатель порций ×1/×2/×4 на странице выдачи подборок. Опиши экраны и действия, состояния (загрузка, пусто, ошибка, выбранные порции), что видит пользователь вместо или рядом с кнопкой «В корзину», пока cart_url существует только для ×1. Код не меняй. В конце отдельным разделом «Что мне нужно от логики»: поля, параметры, ошибки."

## Контекст

Сейчас каждая карточка подборки в выдаче показывает фото товаров, название, описание, теги, итог «≈ 1 111 ₽», кнопку «Перенести в корзину ВкусВилла» (открывает vkusvill.ru в новой вкладке) и раскрывающийся состав-«чек»: товар, количество, единица, цена за единицу. Подборка собрана куратором на один набор — это **×1**. Ссылка на готовую корзину есть только для ×1.

Термины:

- **Множитель (×N)** — во сколько раз увеличить подборку: ×1 — как собрал куратор, ×2 и ×4 — все количества увеличены в 2 и 4 раза.
- **Корзина ×N** — ссылка на vkusvill.ru, которая кладёт в корзину подборку сразу с количествами для ×N.

## Clarifications

### Session 2026-10-21

- Q: Переключатель порций свой в каждой карточке или один общий на страницу? → A: Свой в каждой карточке, по умолчанию ×1; общего переключателя в панели фильтров нет.
- Q: Что делать с зелёной кнопкой корзины при ×2/×4 без ссылки? → A: Заменить: зелёная кнопка исчезает, на её месте подсказка и кнопка второго плана «Открыть корзину ×1».
- Q: Как долго помнить выбранный множитель? → A: До перезагрузки страницы; после перезагрузки и при открытии по ссылке — ×1. В адрес страницы и хранилище браузера множитель не пишется.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Увидеть подборку на ×2 / ×4 (Priority: P1)

Пользователь готовит на компанию. В карточке «Борщ на большую кастрюлю» он нажимает «×2» и сразу видит итог и количества товаров для двух наборов, не уходя со страницы.

**Why this priority**: это основная ценность фичи — понять, сколько купить и сколько это стоит. Работает даже без новых ссылок на корзину.

**Independent Test**: открыть выдачу, в любой карточке выбрать ×2 и ×4 — итог и состав меняются, остальные карточки, фильтры и адрес страницы не меняются.

**Acceptance Scenarios**:

1. **Given** выдача загружена и карточка в ×1, **When** пользователь нажимает «×2», **Then** «×2» отмечен выбранным, итог показывает сумму для ×2 с пометкой множителя («≈ 2 222 ₽ · ×2»), а в составе количества для ×2.
2. **Given** карточка в ×2, **When** пользователь нажимает «×1», **Then** итог, состав и кнопка корзины такие же, как до переключения.
3. **Given** в выдаче несколько карточек, **When** в первой выбран ×4, **Then** остальные карточки остаются в ×1.
4. **Given** в карточке выбран ×2, **When** пользователь меняет запрос или фильтр и эта подборка остаётся в выдаче, **Then** в ней по-прежнему выбран ×2.
5. **Given** фокус на переключателе, **When** пользователь меняет выбор с клавиатуры, **Then** выбор меняется, а программа чтения с экрана объявляет «Порции: ×2, выбрано» и новый итог.

### User Story 2 — В корзину, когда ссылки на ×N нет (Priority: P1)

Так обстоят дела сейчас: корзина есть только для ×1. Пользователь выбрал ×2 и хочет перенести подборку в корзину. Страница честно говорит, что корзины на ×2 нет, открывает корзину ×1 и подсказывает, что поправить на vkusvill.ru.

**Why this priority**: без этого переключатель вводит в заблуждение — кнопка «В корзину» рядом с «×2» выглядит как корзина на ×2, а откроется ×1.

**Independent Test**: при данных, где для ×2 и ×4 ссылок нет, выбрать ×2 в любой карточке: нет ни одной кнопки, обещающей корзину ×2; есть подсказка и кнопка «Открыть корзину ×1».

**Acceptance Scenarios**:

1. **Given** выбран ×2 и ссылки на корзину ×2 нет, **Then** вместо зелёной кнопки «Перенести в корзину ВкусВилла» показан блок: подсказка «Корзины на ×2 пока нет. Откроем корзину на ×1 — на vkusvill.ru увеличьте количество каждого товара в 2 раза», кнопка второго плана «Открыть корзину ×1» и ссылка «Показать количества для ×2».
2. **Given** то же состояние, **When** пользователь нажимает «Открыть корзину ×1», **Then** в новой вкладке открывается та же ссылка, что и в ×1, а переключатель остаётся на ×2.
3. **Given** то же состояние, **When** пользователь нажимает «Показать количества для ×2», **Then** раскрывается состав; в каждой строке количество для ×2 и мелко — для ×1 («2 шт · было 1 шт»), чтобы сверить с корзиной.
4. **Given** выбран любой ×N без ссылки, **Then** ни в карточке, ни в подвале страницы нет текста или кнопки, обещающих перенос корзины на ×N.

### User Story 3 — Корзина ×N одной кнопкой, когда логика её даёт (Priority: P2)

Когда команда 2 начнёт отдавать ссылки для ×2 и ×4, пользователь переносит увеличенную подборку в корзину одной кнопкой, как сейчас ×1.

**Why this priority**: полная ценность фичи, но зависит от логики; до неё работает US2.

**Independent Test**: при данных, где у ×2 есть ссылка, выбрать ×2 — основная кнопка ведёт на ссылку ×2.

**Acceptance Scenarios**:

1. **Given** у ×2 есть ссылка, **When** выбран ×2, **Then** основная кнопка называется «Перенести в корзину ВкусВилла · ×2» и открывает ссылку ×2 в новой вкладке.
2. **Given** ссылку ×2 можно получить только по запросу, **When** пользователь выбирает ×2, **Then** итог и состав уже показаны, а на месте кнопки — неактивная «Собираем корзину ×2…» с индикатором. Пришла ссылка — сценарий 1; ошибка или ожидание дольше 10 секунд — US4.
3. **Given** ссылка ×2 этой подборки уже получена на открытой странице, **When** пользователь уходит на ×1 и возвращается на ×2, **Then** кнопка сразу готова, повторной сборки нет.
4. **Given** идёт сборка корзины ×2, **When** пользователь переключается на ×4, **Then** показывается состояние ×4; поздний ответ для ×2 не появляется под ×4.

---

### User Story 4 — Ошибки и недоступные множители (Priority: P2)

Ссылка не собралась или ×4 физически не помещается в корзину ВкусВилла — пользователь понимает, что случилось, и у него всегда есть запасной путь через ×1.

**Why this priority**: без этого пользователь застревает на неработающей кнопке.

**Independent Test**: смоделировать ошибку сборки ссылки и недоступный ×4 — видны тексты, повтор и запасной путь.

**Acceptance Scenarios**:

1. **Given** сборка корзины ×2 завершилась ошибкой или не уложилась в 10 секунд, **Then** на месте кнопки текст «Не получилось собрать корзину ×2», кнопка «Попробовать ещё раз» и запасной путь из US2 («Открыть корзину ×1» с подсказкой).
2. **Given** логика сообщила, что ×4 для этой подборки недоступен, **Then** «×4» виден, но неактивен, а причина видна под переключателем при фокусе или наведении и объявляется программой чтения с экрана (например, «×4 не поместится в корзину ВкусВилла: больше 40 шт „Яйцо куриное“»).
3. **Given** логика не прислала данных о порциях для подборки, **Then** переключателя в карточке нет, карточка выглядит и работает как сейчас.

### Экраны и состояния

#### Где находится переключатель

В каждой карточке, в блоке покупки, перед итогом: подпись «Порции» и три сегмента «×1 ×2 ×4», выбран ровно один, по умолчанию ×1. В общую панель фильтров переключатель не выносится: итог и ссылка у каждой подборки свои. На узком экране (от 360 px) переключатель стоит отдельной строкой над итогом и кнопкой.

#### Состояния страницы

| Состояние | Что видит пользователь | Переключатель |
|---|---|---|
| Первая загрузка выдачи | строка «Ищем подборки…» на месте выдачи | нет (нет карточек) |
| Обновление выдачи после смены запроса или фильтра | прежняя выдача остаётся на месте до прихода новой | работает; выбор по каждой подборке сохраняется |
| Пусто | как сейчас: «Ничего не нашлось…» и «Сбросить поиск» | нет |
| Каталог не отвечает | как сейчас: «Каталог не отвечает. Обновите страницу через минуту.» | нет |

#### Состояния карточки

| Состояние | Переключатель | Итог | На месте кнопки «В корзину» | Состав |
|---|---|---|---|---|
| ×1 (по умолчанию) | выбран ×1 | ≈ 1 111 ₽ | зелёная «Перенести в корзину ВкусВилла» — как сейчас | количества ×1 |
| ×N, ссылка есть | выбран ×N | ≈ 2 222 ₽ · ×2 | зелёная «Перенести в корзину ВкусВилла · ×2» | количества ×N и «было» для ×1 |
| ×N, ссылка собирается | выбран ×N | итог ×N | неактивная «Собираем корзину ×2…» с индикатором | количества ×N |
| ×N, ссылки нет | выбран ×N | итог ×N | подсказка + кнопка второго плана «Открыть корзину ×1» + «Показать количества для ×2» | количества ×N и «было» |
| ×N, ошибка сборки | выбран ×N | итог ×N | «Не получилось собрать корзину ×2» + «Попробовать ещё раз» + «Открыть корзину ×1» | количества ×N и «было» |

#### Итог и бюджет

- Итог для ×N — число, которое прислала логика; страница его не пересчитывает.
- Фильтр «до 500 / 1 000 / 2 000 ₽» и сортировка по цене работают по итогу ×1 (как в контракте). Если выбран бюджет и итог ×N его превышает, рядом с итогом мелкая пометка «больше бюджета».

| Где | Текст |

| Сегменты | ×1, ×2, ×4 |
| Итог ×N | ≈ 2 222 ₽ · ×2 |

### Edge Cases

- **Весовые товары**: 0,35 кг × 4 = 1,4 кг — дробь через запятую, без лишних нулей; округление количества делает логика.
- **Лимит корзины ВкусВилла** (до 40 на позицию): если ×4 его превышает, логика помечает ×4 недоступным — сегмент неактивен с причиной (US4.2).
- **Округление итога**: итог ×4 может отличаться от «итог ×1 × 4» на рубль-другой — показываем число логики.
- **Быстрое переключение** ×2 → ×4 → ×1 во время сборки: на экране только последний выбор, поздние ответы игнорируются.
- **Подборка ушла из выдачи и вернулась** после смены фильтра: выбор сохраняется до перезагрузки страницы.
- **Перезагрузка или ссылка на выдачу**: все карточки открываются в ×1; множитель в адрес страницы не попадает.
- **Логика прислала ×2, но не ×4** (или наоборот): сегмент без данных неактивен без причины-ошибки, с подсказкой «пока недоступно».
- **Открытие корзины ×1 из состояния ×N**: переключатель не сбрасывается, чтобы пользователь видел нужные количества, пока правит корзину.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Каждая карточка подборки в выдаче MUST иметь переключатель «Порции» с вариантами ×1, ×2, ×4; выбран ровно один, по умолчанию ×1.
- **FR-002**: Выбор в одной карточке MUST NOT менять другие карточки, фильтры, сортировку и адрес страницы.
- **FR-003**: При выборе ×N итог и количества в составе MUST показываться по данным логики для ×N; страница сама их не вычисляет.
- **FR-004**: В составе при ×N каждая строка MUST показывать количество для ×N и, второстепенно, количество для ×1.
- **FR-005**: Основная кнопка корзины для ×N MUST показываться только при наличии ссылки на корзину ×N; её подпись MUST содержать множитель.
- **FR-006**: Если ссылки ×N нет, зелёная кнопка корзины MUST NOT показываться ни с какой подписью; на её месте карточка MUST показать подсказку с конкретным множителем, кнопку второго плана «Открыть корзину ×1» (ссылка ×1, новая вкладка) и способ раскрыть состав с количествами ×N.
- **FR-007**: Если ссылку ×N можно получить по запросу, на время сборки карточка MUST показать неактивную кнопку «Собираем корзину ×N…»; ожидание дольше 10 секунд считается ошибкой.
- **FR-008**: При ошибке сборки карточка MUST показать сообщение, кнопку повтора и запасной путь из FR-006.
- **FR-009**: Недоступный для подборки множитель MUST быть виден, но неактивен; причина MUST быть доступна при фокусе, наведении и программе чтения с экрана.
- **FR-010**: Если данных о порциях нет, карточка MUST выглядеть и работать как до фичи, без переключателя.
- **FR-011**: Выбор множителя MUST сохраняться для подборки при обновлении выдачи до перезагрузки страницы; после перезагрузки и при открытии по ссылке — ×1. Множитель MUST NOT сохраняться в адресе страницы или хранилище браузера.
- **FR-012**: На экране MUST отображаться результат только последнего выбора; ответы для прежнего выбора не показываются.
- **FR-013**: Ссылка ×N, уже полученная на открытой странице, MUST использоваться повторно без новой сборки.
- **FR-014**: Переключатель MUST управляться с клавиатуры; группа имеет подпись «Порции», выбранный вариант и новый итог объявляются программой чтения с экрана.
- **FR-015**: При первой загрузке выдачи страница MUST показывать «Ищем подборки…».
- **FR-016**: Если выбран бюджет и итог ×N его превышает, рядом с итогом MUST быть пометка «больше бюджета»; фильтр и сортировка по-прежнему работают по итогу ×1.
- **FR-017**: Карточка во всех состояниях MUST читаться на экране шириной 360 px без горизонтальной прокрутки.

### Key Entities

- **Вариант порций** — один множитель подборки: множитель (1, 2 или 4), итог в рублях, количество каждого товара, ссылка на корзину или признак её отсутствия, доступность и причина недоступности.
- **Выбор пользователя** — какой множитель выбран в какой подборке на открытой странице; живёт до перезагрузки.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: После нажатия ×2 или ×4 итог и состав обновляются без видимой задержки (до 0,2 с), без перезагрузки выдачи.
- **SC-002**: Ноль ситуаций, где кнопка обещает корзину ×N, которой нет, — проверяется для всех подборок каталога во всех состояниях из таблицы.
- **SC-003**: В коридорном тесте не меньше 4 из 5 участников, выбравших ×2 без ссылки, верно объясняют, что откроется корзина на ×1 и что в ней поправить.
- **SC-004**: От выбора ×N до открытой вкладки vkusvill.ru — не больше 2 нажатий в любом состоянии, кроме «недоступен».
- **SC-005**: Все действия с переключателем выполнимы только с клавиатуры, программа чтения с экрана озвучивает выбранный множитель и итог.
- **SC-006**: Карточка в любом состоянии помещается в экран шириной 360 px без горизонтальной прокрутки.

## Assumptions

- ×N — все количества подборки умножены на N. Сколько человек кормит ×1, неизвестно, поэтому подписи «×1 / ×2 / ×4», а не «на 2 персоны».
- Переключатель свой у каждой карточки, общего на страницу нет (решено в Clarifications): итог и ссылка у подборок разные.
- Множитель не попадает в адрес страницы: ссылкой на выдачу делятся без него.
- Фильтр бюджета и сортировка по цене остаются по итогу ×1 — контракт `docs/requirements.md` (R2) не меняется со стороны UI.
- Готова ли ссылка заранее или собирается по запросу — решает команда 2; спека покрывает оба варианта.
- Ссылка ×1 есть у каждой подборки всегда (правило R3), поэтому запасной путь доступен в любом состоянии.
- Бэкенд, `curate.mjs`, MCP `vv-collections` и контракт — вне этой спеки. Внешний вид при реализации делается через skill frontend-design.

| Список вариантов порций с множителями 1, 2, 4 | рисовать переключатель; нет списка — нет переключателя (FR-010) | `servings: [{ "multiplier": 2, … }]` |
| Итог варианта, целые рубли | итог в карточке (FR-003) | `"total_price": 2222` |
| Количество каждого товара в варианте, по `xml_id`, в той же единице, что у ×1 | состав ×N и «было» (FR-004) | `"quantities": { "114976": 2 }` |
| Ссылка на корзину варианта или явное «нет» | выбрать состояние кнопки (FR-005, FR-006) | `"cart_url": null` |
| Статус ссылки: есть / нет / можно запросить | отличить «ссылки нет» от «соберём» (FR-007) | `"cart": "ready" \| "none" \| "on_request"` |
| Доступность варианта и причина по-русски, для людей | неактивный сегмент с причиной (FR-009) | `"available": false, "reason": "больше 40 шт «Яйцо куриное»"` |

Вариант ×1 должен совпадать с текущими полями подборки (`total_price`, `cart_url`, `products[].quantity`) — без расхождений.

### Параметры

- Если ссылки ×N собираются по запросу — нужен способ запросить ссылку по `id` подборки и множителю (только 1, 2, 4); ответ — ссылка `https://vkusvill.ru/?share_basket=…` или ошибка из таблицы ниже. UI ждёт до 10 секунд.
- Повторный запрос для той же пары «подборка + множитель» желательно отдавать ту же ссылку, а не создавать новую корзину.
- Параметр множителя в поиске (R2) UI **не нужен**: фильтр бюджета и сортировка остаются по ×1. Если команда 2 хочет его добавить — предупредите, это меняет смысл бюджета на странице.

### Ошибки

UI должен различать их по коду, а не по тексту сообщения (предложение: `{"error": "…", "code": "…"}` рядом с нынешним `error`).

| Ситуация | Что покажет UI |
|---|---|
| Подборки нет (как `404` в R4) | «Подборка больше недоступна — обновите страницу» |
| Недопустимый множитель (не 1, 2, 4) | не должно случаться; общий текст ошибки + запасной путь ×1 |
| ×N не помещается в лимиты корзины ВкусВилла (40 на позицию, 20 позиций) | сегмент неактивен с причиной. Лучше знать заранее из `available`/`reason`, а не узнавать ошибкой при запросе |
| ВкусВилл не создал ссылку или не отвечает | «Не получилось собрать корзину ×N» + повтор + запасной путь ×1 |
| Логика не ответила за 10 секунд | то же, что предыдущая строка |
