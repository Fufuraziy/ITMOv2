# Style guide

Пять правил, которые проверяются кодом или видны в ревью.

1. **Поведение проверяется через публичный интерфейс.** Тесты бэкенда идут через `collections.Service` и HTTP-обработчики, а не через приватные поля. Пример: `backend/internal/httpapi/handler_test.go`, `TestAPI_SearchBadQuery`.
2. **Ошибки — значения, а не строки.** Проверка каталога возвращает `*collections.ValidationError` со списком всех проблем, отсутствие подборки — `collections.ErrNotFound` (через `errors.Is`). Сообщения в нижнем регистре, без точки. Пример: `backend/internal/collections/validate.go`.
3. **`context.Context` первым параметром** у всего, что ходит в хранилище (`Store`, `Service`). Postgres-реализация получит его без смены интерфейса.
4. **Без фреймворков ради маленькой правки.** Бэкенд — только стандартная библиотека (`net/http` с шаблонами маршрутов Go 1.22+). Новая зависимость — только с обоснованием в PR.
5. **Не ослабляй runner ради зелёного результата.** `scripts/check.sh` (gofmt → vet → test) меняется только по отдельному поручению; `t.Skip` и удаление чужих тестов запрещены.
