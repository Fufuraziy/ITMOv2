# Контракт сервиса поиска подборок

Пользователь открывает страницу, находит тематическую подборку товаров ВкусВилла («Завтрак с сырниками», «Борщ на большую кастрюлю») и одной кнопкой переносит её в корзину на сайте ВкусВилла. **Пользователи подборки не создают**: каталог собирает куратор.

Как появляется каталог: темы с поисковыми запросами в `catalog/themes.json` → `node mcp/vv-collections/curate.mjs` ищет товары через MCP ВкусВилла (`vkusvill_products_search`), создаёт ссылку на корзину (`vkusvill_cart_link_create`) → `backend/catalog/collections.json`. Бэкенд встраивает этот файл и только читает его.

## Модель

```json
{
  "id": "zavtrak-s-syrnikami",
  "title": "Завтрак с сырниками",
  "description": "Сырники разогреть на сковороде, подать со сметаной и вареньем…",
  "tags": ["завтрак", "сладкое", "быстро"],
  "cart_url": "https://vkusvill.ru/?share_basket=3549115194",
  "total_price": 1111,
  "products": [
    {
      "xml_id": 114976, "name": "Сырники классические жареные",
      "quantity": 1, "unit": "шт", "price": 306, "rating": 4.9,
      "url": "https://vkusvill.ru/goods/syrniki-klassicheskie-zharenye-114976/",
      "image": "https://img.vkusvill.ru/pim/images/site/site_BigWebP/….webp"
    }
  ]
}
```

- `price` — цена за `unit` (шт или кг) в рублях на дату `updated_at` каталога; `quantity` — сколько положить в корзину (для кг — дробное).
- `total_price` — вычисляет бэкенд: округлённая сумма `price × quantity`. Из файла не берётся.

## R1. Каталог при старте

- Бэкенд проверяет каждую подборку по R3 и уникальность `id`. При нарушениях не запускается и перечисляет **все** проблемы в виде `<id>: <поле>: <проблема>`.
- Каталог в репозитории всегда проходит R3 (это проверяет тест).

## R2. Поиск — `GET /collections`

Параметры (все необязательные):

| параметр | смысл |
|---|---|
| `q` | слова через пробел; подборка подходит, если **каждое** слово встречается в названии, описании, тегах или названиях товаров. Без учёта регистра, `ё` = `е` |
| `tag` | подборки с этим тегом (без учёта регистра) |
| `max_price` | целое > 0: `total_price ≤ max_price` |
| `sort` | `catalog` (по умолчанию, порядок каталога), `price_asc`, `price_desc` |

- Ответ `200`: `{"updated_at": "2026-10-06", "total": 2, "collections": [...]}`. Ничего не нашлось — `"collections": []`.
- Неверный `max_price` или `sort` — `400 {"error": "invalid query: ..."}`.

## R3. Правила каталога

| поле | правило |
|---|---|
| `id` | латиница в нижнем регистре, цифры и дефисы: `^[a-z0-9]+(-[a-z0-9]+)*$` |
| `title` | 3–80 символов |
| `description` | 1–500 символов |
| `tags` | 1–6 тегов, каждый 2–24 символа, без повторов |
| `cart_url` | начинается с `https://vkusvill.ru/?share_basket=` |
| `products` | 1–20 товаров (лимит корзины ВкусВилла) |
| `products[i].xml_id` | целое > 0, не повторяется внутри подборки |
| `products[i].name` | 1–120 символов |
| `products[i].quantity` | 0.01–40 (лимит корзины ВкусВилла) |
| `products[i].price` | > 0 |
| `products[i].url` | начинается с `https://vkusvill.ru/goods/` |

Символы считаются как руны Unicode, не байты.

## R4. Подборка по id — `GET /collections/{id}`

- `200` и подборка; `404 {"error": "collection not found"}`, если нет.

## R5. Теги — `GET /tags`

- `200 [{"tag": "завтрак", "count": 2}, ...]` — по убыванию `count`, при равенстве по алфавиту.

## R6. Исключение слов (запланировано, фича для демо-сессии)

- Слово в `q` с префиксом `-` исключает подборки, где оно встречается (там же, где ищутся слова R2): `q=завтрак -сырники`.
- Запрос только из исключений (`q=-мясо`) — весь каталог без подборок с этим словом.
- Одиночный `-` и пустые слова игнорируются.

## Прочее

- Любой другой метод — `405`. Создания подборок через API нет.
- Хранилище — интерфейс `Store` (`List`, `Get`); сейчас `MemoryStore` поверх встроенного каталога, Postgres — следующий шаг.
